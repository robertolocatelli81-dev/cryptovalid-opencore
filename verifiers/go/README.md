# cryptovalid — Go reference (verifier + writer)

Stdlib-only Go implementation of the cryptovalid evidence-ledger profile
(`SPEC_EVIDENCE_FORMAT.md` §3-4, `spec/CONFORMANCE.md`). Two things a Go service such as an audit log needs:

* **`cryptovalid.Append(path, ts, data, "sha256")`** — what a writer does at insert time: canonical JSON
  (sorted keys, no whitespace, ASCII-escaped, no floats, no duplicate keys, integers within +/-(2^53-1),
  nesting <= 512, no unpaired surrogates), `prev_hash` of the last line, SHA-256 -> one JSONL line.
  O(1) per append (last line read backwards), exclusive `flock` from tail-read to fsync on Unix.
* **`cryptovalid.VerifyLedger(r)`** / `cmd/cvverify` — single-snapshot verification in streaming (one entry
  in memory): every `self_hash` recomputes, every `prev_hash` links, `idx` contiguous from 0.
  Exit 0 PASS, 1 FAIL (an empty ledger is FAIL: nothing verified).

```
go test ./...                                   # vectors.json (Python reference bytes) + refusals + chain
go run ./cmd/cvverify ledger.jsonl
echo '{"actor":"alice","status_code":200}' | go run ./cmd/cvappend ledger.jsonl 2026-09-14T17:30:00Z
```

**Cross-language evidence (14/09/2026).** `vectors.json` is generated by `vectors.py` from Python's stdlib
`json` (the normative reference): Go reproduces every byte, including code-point key ordering
(U+FFFF before U+1F600), surrogate pairs, U+2028, U+00A0, DEL, control characters, and NFC vs NFD e-acute
kept distinct. A 200-row ledger written by `cvappend` is byte-identical to the one Python builds; on 6003
enumerated tampers of that ledger `cvverify`, `verifier.py` and `cvverify.mjs` give the same verdicts
(6002 detected; the one miss is the deleted LAST row, invisible to any hash chain on a single snapshot:
`cryptovalid_monitor.py`, receipts or an external anchor cover it). The refusals (`vectors.json` -> `refuse`)
are identical in the three languages: float, duplicate key, |int| > 2^53-1, nesting > 512, lone surrogate,
invalid UTF-8.

**Declared limits.** No signature verification here (use `signer.py` / receipts). `flock` is advisory and
per process: threads of one process need their own mutex; on non-Unix builds there is no lock at all.
Go's `json.Marshal` turns a whole-number `float64` into an integer and replaces non-UTF-8 bytes in Go
strings with U+FFFD before `Append` sees them: validate at the source.
